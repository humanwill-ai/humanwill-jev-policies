## Credential correction

The OpenRouter credential was already stored in macOS Keychain under service `org.humanwill.evals.openrouter`, account `api-key`. Earlier checks inspected only environment variables and repository `.env` files and therefore missed it. The `security` command found the entry but timed out reading it; that attempt made **no API call**. The existing native HumanWill Keychain helper in the sibling benchmark checkout then read it successfully into Python memory. It was used only in the smoke process, never printed, written to disk, or added to command arguments. The temporary environment reference was removed afterward.

No Keychain implementation was copied into this package and no benchmark dependency was added. Normal deployments still use configured environment references. For future local runs, check the documented Keychain entry before asking for a replacement key; invoke the existing helper only inside a process that consumes the value without printing it. Do not run a password-returning shell command directly into tool output.

A targeted lookup found no entry under `org.humanwill.evals.typesafe` / `api-key`; this does not rule out a differently named credential. The separate direct-provider smoke gate remains pending a TypeSafe credential. The successful OpenRouter call does not test the direct endpoint. No additional live calls are needed to reproduce this report; proceed to the next authorized implementation work without treating this single observation as accuracy, adversarial robustness, or a latency distribution.
